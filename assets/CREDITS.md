# Asset provenance

Every file under `assets/` came from somewhere, and this records where. The
rule the rest of this repository follows applies here too: a thing is
described as what it is, not as what it would be convenient for it to be.
None of these are source-authored art, and none is claimed to be.

Source repository for all of them: `dylmarriner/Maer-Ken`, commit
`3508e61710749d35a22c0f0dac27a61350639ad2`, imported 2026-10-08. Both
repositories carry the same licence — copyright Dylan Marriner, all rights
reserved — so this is one owner's work moving between two of their own
projects, not a third-party import.

## The estate: buildings, computers, tools, vehicles

From upstream `apps/mk_ui/assets/generated/gem_property/`, generated by
`tools/assets/generate_gem_property_assets.py` (vendored alongside them, so
they can be regenerated rather than only trusted).

Upstream's own description, carried over because it is the honest one: these
are *deterministic low-poly Maer-Ken reconstructions from the in-repository
property manifest*, not exports from the Gemini Universe source the manifest
describes — that repository is unavailable. They are built by a Blender
script from primitives, and they look it.

| Directory | Files | What they stand for |
|---|---|---|
| `property/buildings/` | `homestead_house`, `equipment_shed`, `building_workshop`, `secure_armoury`, `computer_room` | Five of the six `PropertyBuildingKind` variants. `Garage` has no model and the renderer says so rather than substituting the shed. |
| `computers/` | `primary_workstation`, `portable_laptop`, `local_archive_server`, `network_equipment_rack` | The `PropertyItemKind::Computer` items in the computer room. The mapping from item name to model is in `apps/island_ui/src/property.rs` and is a table, not a guess: two of the four names match the manifest exactly (`Local Archive Server`, `Network Equipment Rack`) and the founders' two machines are mapped to `primary_workstation` and `portable_laptop`, which is a choice recorded there. |
| `tools/` | seven `BuildingEquipment` models | Workshop equipment. |
| `property/armoury/` | three `ArmouryItem` models | |
| `property/household/` | three `HouseholdItem` models | |
| `vehicles/` | `utility_truck`, `all_terrain_utility_vehicle`, `motorbike`, `utility_trailer` | The named vehicles in the manifest. |

`ShedTool` and `VehicleAttachment` have no models upstream either. The
renderer draws them as untextured placeholder boxes and the key says that is
what they are.

## Terrain and biome materials

From upstream `apps/mk_ui/assets/generated/maerken_terrain_materials/`,
generated by `tools/assets/generate_maerken_terrain_materials.py` (also
vendored). 52 PNG textures across 13 material families (base colour,
roughness, normal, emission) and 21 biome preview GLBs matching `BiomeType`
in `mk_core`.

Upstream's caveat, which applies here with more force: *these are
deterministic material previews; they are not claimed to be source-authored
art.* The island renderer uses the colour maps as surface textures over its
own simulated heightfield — the geometry and every value shading it come
from the simulation, never from these files.
