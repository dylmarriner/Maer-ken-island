# Session log: 2026-10-23

The owner's goal: **"get 100% production ready and finish all remaining work"**, with two Claude
sessions working in parallel. The owner insisted that neither should wait on the other's builds.
This is the map. The commit messages and PR descriptions carry the detail.

## How the two sessions worked

- **One build lock.** Every build, clippy or test run goes through
  `flock /tmp/mk-build.lock <command>`, started in the background, with each worktree's own
  `CARGO_TARGET_DIR` (its `target/`). A session never waits on the lock. It keeps coding in
  another worktree and folds the new commits into the branch whose check is queued, so one run
  checks as much as possible.
- **One check and one re-pin per PR.** `WEEK_DIGEST` is re-pinned once, at the end, after a
  message to the other session. Whoever merges second rebases and re-pins.
- **Split by area**, settled by message (when two messages crossed, the one marked FINAL won).
- **The owner's rulings** about people (R11-R14, below) bind both sessions. Nobody is told what to
  do. Choices come only from the human runtime, and skill, fitness and genes are kept per agent
  id for **every** human, not only the founders.
